## 이 문서를 보는 법

**회의에서는 이 문서 하나만 본다.** 각 안건은 "무엇을 정해야 하는지"와 "정하지 않으면 무엇이 막히는지"만 적는다. 기술적 배경이 필요하면 아래 문서를 연다.

| 문서 | 용도 |
| --- | --- |
| `SOUND_IMPLEMENTATION_STATUS.md` | 현재 구현 상태, 담당 경계, 확인된 문제 |
| `GDD_SOUND_CHANGE_REQUESTS.md` | GDD에 반영해야 할 수정 요청 목록 |

안건은 **차단 정도** 순으로 정렬했다. A는 결정 전까지 작업을 시작할 수 없는 것, B는 작업은 가능하나 되돌릴 위험이 있는 것, C는 정보 공유다.

## A-1. BGM 상태 정의를 GDD와 일치시킨다

**결정할 것:** 아래 네 가지를 코드 기준으로 확정할지, GDD 기준으로 코드를 고칠지.

| 쟁점 | GDD 14.1 | 현재 코드 |
| --- | --- | --- |
| `SAFE` 상태 | 있음 | 없음 (3단계 + ENDING) |
| TENSION 범위 | 같은 Zone **또는 인접 Zone** | 같은 Zone만 |
| TENSION 추가 조건 | 소음을 **조사 중**일 때도 | 조사 여부를 보지 않음 |
| AMBIENT 조건 | "긴장도가 낮은" | `GlobalStress` 미사용 |
| ENDING 조건 | 발전기 완료 **+ 탈출 장치 활성화** | 발전기 완료 즉시 |

**사운드 측 의견:** SAFE 제거와 ENDING 조건 변경은 2026-08-03에 이미 구두 확정했으나 GDD에 반영되지 않았다. 나머지 세 가지는 미확정이다.

인접 Zone과 조사 중 조건은 **반대한다.** Director 힌트는 부정확한 Zone을 가리키므로(GDD 9.4), 조사 중이라는 이유로 긴장 음악을 켜면 AI가 맵 반대편을 뒤지는 동안에도 음악이 유지된다. 플레이어에게 위치 정보를 주는 대신 노이즈만 준다(GDD 3.1).

**막히는 것:** 확정 전에는 PR #15를 병합해도 기준이 두 개인 상태로 남는다.

## A-2. 전기 스파크의 발생 조건

**결정할 것:** 전기 스파크가 QTE 실패 연출인지, 완료 연출인지, 그리고 사운드인지 VFX인지.

GDD가 세 곳에서 다르게 말한다.

| 위치 | 서술 |
| --- | --- |
| 7.4 QTE 규칙 | "실패 시 붉은 피드백, **스파크**, 큰 소음을 제공한다" |
| 14.2 발전기 필수 효과음 | "**완료음과 전기 스파크**" |
| 12장 환경 사운드 | "전기 스파크와 금속 충격" |

**사운드 측 의견:** 7.4의 스파크는 "붉은 피드백"과 나란히 있고 같은 줄에서 사운드는 "큰 소음"이 맡고 있으므로 **시각 연출로 읽힌다.** 14.2가 이를 필수 *효과음* 목록에 넣은 것이 혼선의 원인으로 보인다. 12장의 환경 스파크는 위 둘과 무관한 별도 항목이다.

**막히는 것:** 조건이 정해지지 않아 착수할 수 없다. 실패 연출이면 기존 `Hit_Metal.wav`를 교체·중첩하는 문제, 완료 연출이면 별개 추가 작업, VFX면 사운드 담당 영역이 아니다.

## A-3. 웹 빌드 오디오 예산

**결정할 것:** BGM 음질을 어디까지 낮출지, 그리고 오디오 총 다운로드 용량 상한.

빌드 타겟이 WebGL이므로 제약이 크게 다르다.

- **WebGL은 Streaming을 지원하지 않는다.** 클립을 통째로 받아야 재생이 시작된다.
- 현재 BGM 3개는 44.1kHz 스테레오, 합계 **약 40MB**다 (83초 / 119초 / 32초).
- 오디오 에셋 전체는 107개 약 261MB이며, 실제 연결된 것은 BGM 3개와 발전기 6개뿐이다.

**사운드 측 의견:** 앰비언스 계열은 고주파 성분이 적어 샘플레이트를 낮춰도 체감 손실이 작다. 모노 변환은 용량이 절반이 되지만 호러 앰비언스의 공간감을 해치므로 BGM에는 권하지 않는다. 구체적인 권장 설정은 `SOUND_IMPLEMENTATION_STATUS.md`에 정리했다.

**막히는 것:** 상한이 없으면 임포트 설정을 정할 수 없고, 초기 로딩 시간이 통제되지 않는다.

## A-4. 레거시 Input 때문에 프로젝트가 실행되지 않는다

**사운드 담당 영역이 아니다.** 사운드 검증 중에 발견해 옮겨 적는다. 결정은 에셋을 도입한 담당자들이 한다.

**결정할 것:** `activeInputHandler`를 `Both`로 확정할지, 레거시 `Input` 사용처를 없앨지.

프로젝트의 Active Input Handling은 `Input System Package`인데 레거시 `UnityEngine.Input`을 쓰는 코드가 남아 있어 컴파일이 실패한다. **`.asmdef`가 UniTask 외에 없어 `05_Assets`의 에셋 팩 스크립트까지 전부 `Assembly-CSharp` 하나로 함께 컴파일되므로, 한 줄만 남아 있어도 어셈블리 전체가 실패하고 아무것도 실행되지 않는다.**

| 사용처 | 내용 | 도입 |
| --- | --- | --- |
| `AI/Debug/AIDebugPresenterHost.cs:45` | `Input.GetKeyDown`, 디버그 패널 토글 (팀 코드, 유일) | `bf747f3` |
| `05_Assets/CleanFlatUI` | ContextMenu 3개, Tooltip 2개, WindowResize의 `Input.mousePosition` | `4ef59e0` |
| `05_Assets/Flooded_Grounds` | FPSController, ExampleWheelController의 `Input.GetAxis`, `GetKey` | `d823d28` |

**선택지**

1. `activeInputHandler`를 `Both`로 확정하고 커밋한다. 가장 간단하지만 프로젝트 전역 결정이다
2. 쓰지 않는 에셋 팩 스크립트를 삭제한다. `Flooded_Grounds`의 FPSController와 ExampleWheel은 데모 코드이며 프로젝트에 자체 `PlayerController`가 있다. CleanFlatUI 쪽은 해당 UI 프리팹을 실제로 쓰는지 확인이 필요하다
3. 에셋 팩을 `.asmdef`로 분리해 격리한다. 외부 코드를 고치지 않아도 되지만 손이 많이 간다

**현재 상태:** 로컬에서 `activeInputHandler`를 `Both`로 바꿔 실행만 시키고 있으며 **커밋하지 않았다.** 저장소 값은 여전히 `Input System Package`이므로 다른 작업자도 같은 문제를 겪는다.

## B-1. 볼륨 설정 인터페이스

**결정할 것:** 사운드 측이 노출할 훅의 형태와, 설정 값 저장 주체.

GDD 13.2는 사운드 설정으로 전체 볼륨·배경 음악·효과음 세 가지를 요구한다. 13장이 UI 챕터이므로 **설정 화면과 저장은 UI 담당 영역**이다. AudioMixer에는 `MasterVolume` / `BgmVolume` / `SfxVolume` 파라미터가 이미 노출되어 있다.

**사운드 측 의견:** 사운드는 "이 세 값을 적용하는 훅"까지만 제공하고, 설정 화면과 저장 데이터는 UI 담당이 소유한다. `GeneratorQteProvider`의 QTE 키를 UI 담당 키 설정 시스템으로 넘기기로 한 것과 같은 방식이다.

**되돌릴 위험:** 합의 없이 사운드 쪽에서 설정 저장까지 만들면 UI 담당 작업과 중복된다.

## B-2. `ChaseAISound` 배선 담당

**결정할 것:** 클립 선정과 믹서 그룹 연결을 누가 언제 할지.

`ChaseAISound.cs`는 구현이 끝났으나 `AI_Prototype`에서 `_outputMixerGroup`이 비어 있고 클립 배열 12개가 모두 비어 있어 **소리가 나지 않는다.**

**사운드 측 의견:** 믹서 그룹 연결은 사운드 공용 구조에 속하므로 사운드 측이 처리할 수 있다. 발소리·울음소리 클립 선정은 AI 연출 의도를 아는 담당자 몫이다.

## B-3. 씬 통합 일정

**결정할 것:** 통합 씬에 사운드를 붙일 수 있는 시점.

빌드에 등록된 `SampleScene`은 카메라와 조명만 있는 빈 씬이다. 플레이어와 AI, 발전기가 서로 다른 씬에 흩어져 있어 **현재 빌드를 실행하면 BGM과 발전기 효과음이 재생되지 않는다.**

**현재 방침:** 사운드는 `AI_Prototype`에서 검증만 하고 씬 변경은 커밋하지 않는다. 산출물은 프리팹과 코드로만 남긴다.

## C-1. 발전기 QTE 입력 래치 (공유)

`PlayerQTEInputSource.IsQteKeyDown()`은 읽으면 소비되는 래치인데, 플래그가 QTE와 무관하게 Space를 누를 때마다 켜진다. `Generator`는 QTE 활성 중에만 이 값을 읽으므로, 평소 점프로 켜진 플래그가 남아 있다가 **QTE 첫 프레임에 소비되어 즉시 실패로 판정된다.**

QTE 효과음을 검증할 때 실패음만 계속 들린다면 사운드 배선이 아니라 이 문제다. 입력 담당 확인이 필요하다.

관련해서 `GeneratorQteProvider._qteKey`는 현재 동작하지 않는 필드다. `KeyboardInputSource` 생성이 주석 처리되어 실제 키에도 UI 라벨에도 반영되지 않는다.

## C-2. 심장 소리 (예고)

플레이어와 Chase AI의 거리에 따라 심장 소리 속도가 변하는 기능은 사운드 담당 범위이나 아직 설계 논의 전이다. 다음 회의 이후 별도로 다룬다.

논의가 필요한 지점은 세 가지다. 거리 계산에 쓸 기준(직선 거리 / 경로 거리 / Zone), BGM `TENSION`과 역할이 겹치지 않게 하는 방법, 그리고 이 소리가 AI에게 들리는 소음이 아니라 플레이어 전용 연출이라는 점의 명시다.
